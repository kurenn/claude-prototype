# Design A/B — anti-slop port (baseline `d90c031` vs candidate `c0a4c7f`)

**Date:** 2026-07-25 · **Brief:** `benchmark/briefs/onboarding-agentic.md` (agentic
onboarding-workflow builder, banking/KYC) · **n = 2 per side** (first wave of the full
rebench; anchor brief only).

## What was compared

- **Baseline** `d90c031` — main + PR #11, *before* the anti-slop port.
- **Candidate** `c0a4c7f` — main + PRs #28–#33: pre-emit self-critique, precise slop gates
  22–33, microinteraction pack, anti-fingerprint nav catalog, enriched inspiration/study
  step, scaffold typography hardening.

Both sides carry the type/palette **rotation menus** already (they shipped in PR #11, which
is the baseline), so those are *not* the delta under test.

## Method + honesty caveats (read before the numbers)

- **Subagent-simulated builds, not live `/prototype` sessions.** Each build was a fresh
  Sonnet agent instructed to *follow the pinned skill files* in a worktree
  (`bench-baseline` @ d90c031 / `bench-candidate` @ c0a4c7f), Quick mode, brief verbatim,
  fallback mode (no impeccable/prompt-refiner/claude-in-chrome; builtin-lint only),
  autonomous direction-confirm. Symmetric on both sides → fair for the A/B, but an
  approximation of a real interactive skill run, not identical to one.
- **n = 2 is directional, not proof.** Taste is noisy; a 1–1 split at n=2 is the
  quality-neutral outcome, not a measurement. See `rebench.md` for the full n=2–3 × 4-brief spec.
- **Both blind judges (Opus, screenshots only) independently picked their "B" folder.** The
  A/B side was flipped per pair (pair 1: A=candidate, B=baseline; pair 2: A=baseline,
  B=candidate), so "both picked B" maps to *different* skill versions — it cancels for the
  version question. A residual "prefer second-shown" bias can't be fully excluded at n=2.

## Win-rate

**1 baseline win, 1 candidate win — a 1–1 split. Quality-neutral at n=2.**

The split was driven by **per-build variance, not a systematic skill effect** — each side
shipped one strong build and one flawed one:

- **baseline/onboard-2** (lost pair 2): its Results Dashboard **rendered completely empty** +
  control-bar clipping — a broken screen that cascaded across hierarchy/cohesion/integrity/gut-check.
  *Caveat:* an empty render can also be a JS-timing artifact (dashboard content injected from
  `data.js`); it is the failure *class* the candidate's stricter assess targets, but shouldn't
  be over-claimed from one screenshot.
- **candidate/onboard-1** (lost pair 1): judged the sparser build — near-invisible (low-contrast)
  funnel bars, a detached step-library panel leaving a desktop dead-zone, a clipped Notifications
  tab at 768. **Yet its pre-emit self-critique passed every axis at 4–5** — i.e. the self-critique
  *over-rated its own output*, the exact rubber-stamp risk PR #28's Fable review flagged. Real
  finding: the self-critique needs the score-stamp to be adversarial, not self-congratulatory.

## Where the candidate *did* clearly earn its keep (process, not pixels)

Not visible to a screenshot judge, but real and one-sided:

- **New guardrails fired.** Both candidate builds ran the **pre-emit self-critique** (stamped
  per screen) and the full **33-rule** builtin-lint; baseline ran 21.
- **Caught bugs baseline shipped.** Candidate builds' assess passes caught + fixed: a mobile
  layout bug overflowing **3/4 screens at 390px** (via `check-overflow.sh`), sub-4.5:1 contrast
  on chips/badges/nav, dead `href="#"` consent links, and `data-loading` handler conflicts that
  would have silently killed the agent-draft submit and step-advance. Baseline's weakest build
  shipped an empty dashboard.
- **Sharper design decision-making.** candidate/onboard-1 chose a **teal accent, not the menu's
  default pine-green**, explicitly reasoning a KYC product already uses green for "verified" and a
  green brand accent would collide with its own status vocabulary — a category-reflex call the
  enriched skill is meant to induce.

## Monoculture / design-diversity (per §4, focus = nav shape this run)

| Side | Display font (both builds) | Palette family | Nav shapes | Signature move |
|---|---|---|---|---|
| baseline | Hanken Grotesk (both) | pine (both) | top-nav **+** side-rail | Agent Rail / Agent Trace Rail |
| candidate | Schibsted Grotesk (both) | teal **+** pine | side-rail + side-rail | Agent Draft Overlay / Agent Draft rail |

- **Type/palette:** each side converged on **one display font** across its two builds
  (expected — shared menus, small n). Candidate diversified the **accent** (teal vs pine, the
  teal reasoned); baseline did not (pine + pine).
- **Nav:** baseline had **more** nav *variety* here (top + rail) than candidate (rail + rail) —
  but both candidate rails were menu-justified, and one dropped chrome on the applicant screen (a
  considered IA move). Honest read: for a 3–4-section ops tool the side-rail is the *right* answer,
  and both candidate builds found it; the anti-fingerprint catalog did not manufacture extra
  variety on this brief. Signature moves converged on an agentic-reasoning surface on **both**
  sides — that's brief-driven, not skill-driven.

## Verdict

**No regression, and the strongest single build in the set was a candidate — but raw visual
quality is a wash at n=2 (1–1).** The port's value shows up as **QA rigor, real bug-catching,
and sharper decision articulation**, not as a systematically better-looking screenshot. Two
concrete follow-ups this run surfaced:

1. **The pre-emit self-critique over-rates its own work** (candidate/onboard-1 scored itself 4–5
   while the blind judge found it the weaker build). Worth making the self-critique adversarial —
   score *against* the brief skeptically, or cross-check the stamp against builtin-lint findings.
2. **The anti-fingerprint nav catalog didn't add nav variety on this brief** because the side-rail
   is the natural answer; its value is more likely on brief types where the reflex nav is a poor
   fit but tempting (marketing-ish app shells).

**Not proof.** n=2, one brief, subagent-simulated. A real claim wants the full spec: n=3 × the
four briefs (`onboarding-agentic`, `saas-dashboard`, `marketplace`, `fintech-app`), with the
self-critique-optimism check repeated across them.
