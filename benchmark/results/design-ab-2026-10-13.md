## Method + honesty caveats

- **Subagent-simulated builds**: each build was a fresh Sonnet agent following a pinned copy of
  the skill (`git archive`). Quick mode, brief verbatim. The agent approved its own
  direction. There was no browser harness, so neither side did a Tier 2 live site search.
- **Blind ranking by one human** (the maintainer): random folder codes, shuffled ports, and
  the key stayed sealed until the ranking came in. There was one rater, n=2 per cell, so
  the result shows a direction, not proof.
- **Shared-scratchpad collisions**: two coffee-PR agents (garnet, iris) and one banking-PR
  agent (pike) wrote to the shared scratchpad at the same time. A check afterwards found no
  foreign files in any build, and each build's own fixes were present. The risk is low but
  not zero.

## Reading it

- **Coffee (retail) is a domain the corpus doesn't cover.** The corpus is dev-tool and
  AI-native, and the main runs said so ("the rest of the corpus didn't apply"). The PR runs
  fetched trader-joes, aesop, starbucks and sweetgreen. They took secondary moves from them,
  such as a printed-flyer serif voice, one drenched hero band and hairline discipline. That is
  where they differ from the main runs.
- **Banking × dev tools is a domain the corpus covers well.** All four directions converged
  on the same palette, type and signature:
  - near-black with a single `#b0805a` clay/copper "held" accent;
  - Schibsted Grotesk with Plex or Public Sans;
  - a mono policy trace.

  The PR runs added mercury, stripe and ramp (tabular figures, one CTA per band). That added
  little the corpus hadn't already given them, and ember's warm-tinted ground and sand theme
  (from ramp) ranked last.
- **Hypothesis:** the index helps where the corpus is thin and is neutral to slightly
  negative where the corpus is already strong. It is consistent with this round but not
  proven at n=2.

## Coffee rerun (2026-10-16) — vendored files, then the font rule

**Round 3a, vendored files (`aeb7169`) vs main:** not ranked. The maintainer stopped on the
headers: all four builds shipped **Bricolage Grotesque**, the first face in the `playful` row of
`type-pairings.md`. Both PR runs read `oura` and `starbucks`, and both threw away the free fonts
those files suggest. Independent runs can't follow "vary it across runs", so all of them took the
first option.

**Round 3b, font rule (`d32f47d`) vs main:** the matched file's free fonts now win, and
`type-pairings.md` is the fallback. There were two new PR builds. The two main builds came from
3a and hadn't been ranked, so they were still blind. Ports were shuffled again.

|---|---|---|---|---|
| 1 | 8643 (kite) | PR | Lora / Nunito Sans | Starbucks file's named substitutes |

| 3 | 8644 (basalt) | main | Bricolage Grotesque / Newsreader | menu, playful row |

The PR builds took both top places. loam ranked 2nd even though it fails the 390px check: its
Account table overflows, from the scaffold's `.proto-table-wrap` bug. kite was also the first
coffee build in three rounds to leave periwinkle with marigold (it used milk, night-indigo and
persimmon), so following a design file's fonts loosened the palette convergence too.

So far this is the clearest result for the design files: they win when they're allowed to
decide something, here the fonts, instead of being read and then overridden by the menus.

## Ledgerline round (earlier, not blind)

The Ledgerline fintech brief ran once per side. Both scored 177/177 and passed at 390px.
The directions were nearly identical, because both took their palette and type from the
rotation menus. The PR run added Mercury as a reference: the main run's live fetch of
mercury.com timed out. The maintainer preferred the PR build, but they knew which was which.

## Side finding: convergence

On each brief, all four runs picked nearly the same palette and signature, regardless of
side. On coffee, all four chose periwinkle with marigold and a moon-phase roast scale. On
banking, all four chose near-black with clay. The rotation menus and the anti-reflex rules
dominate the direction, and inspiration only moves secondary choices. That is worth its own
look: two runs of the same brief should not converge this tightly.

## Follow-ups

- Possible skill change: grep the index only when the brief's domain isn't covered by the
  corpus, or when the user names a brand. Retest before shipping it.
- Scorer: exempt the default layout from "every layout has a CSS rule".
- Scaffold bugs seen across runs: `.proto-table-wrap` needs `position: relative`; `state.js`
  rewrites the URL on load; the control bar is too wide at 1440px.
